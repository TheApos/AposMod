# AposMod — project notes for Claude

7 Days to Die mod: Borderlands-style traits for each weapon class (shotgun slugs knock back, grenades x3 radius, melee normal/power effects, pipe-weapon "veteran" bonus, early rocket launcher, floating damage numbers).

- Game version: **V3.4.0 (b6)**. Always verify against the installed game files in `../../Data/Config` (items.xml, buffs.xml, loot.xml, entityclasses.xml, Localization.csv) — do not guess XML names or engine behavior.
- The owner speaks Ukrainian (answer in Ukrainian) and is learning modding — explain briefly.
- Ideas and implementation status: `docs/WeaponIdeas.md`. In-game test steps: `docs/TestChecklist.md`. Weapon list: `docs/Weapons.md`. Balance review: `docs/BalanceAnalysis.md`.
- Player-facing reference page: `docs/Reference.html`, published as a private artifact at https://claude.ai/artifact/C9rHeAvrTK86bwcwhjAHvm and on GitHub Pages — keep it in sync with gameplay changes and republish (same file path or that URL). It is **generated** (English default, Russian, Ukrainian switch): edit `docs/i18n/body.{en,ru,uk}.html` (same markup in all three), `head.html`, `script.js`, then run `& docs/i18n/build_reference.ps1`. Never edit Reference.html by hand. The mod version on the page is `{{VERSION}}`, filled from ModInfo.xml: after a version bump rebuild the page and push.

## Layout
- `ModInfo.xml` — mod name/version (bump on releases).
- `Config/*.xml` — XPath patches (`set`, `append`, `insertBefore`, `remove`, `csv`) over vanilla configs. `progression.xml` hides Grand Slam (its Rage is in the club mastery tree; spent points are refunded by AposMastery.RefundGrandSlam), replaces Intellect Mastery 4-5 with Field Repair / Inventor, and removes vanilla perk mechanics that duplicate mod traits or mastery trees (Pummel Pete / Skull Crusher / The Brawler knockdowns, Gunslinger and Pummel Pete combos, Pummel Pete stunned bonus, Deep Cuts normal-hit bleeding).
- `Config/Localization.csv` — must be **.csv** (game 3.x ignores Localization.txt). Columns `english` and `russian`; **fill both** (the game client runs in Russian; an empty column shows a blank text).
- `Source/*.cs` — C# part. Build: `& Source/build.ps1` → `AposMod.dll` (gitignored).
- `Source/gen_loc.ps1` — regenerates `Config/Localization.csv` (vanilla text + trait, EN/RU). Edit trait texts there, not in the CSV. Keep it UTF-8 **with BOM**.
- Damage numbers (AposMod.cs): the game's own 3D `DamageText` (world option, created in `EntityAlive.ProcessDamageResponseLocal`), restyled by Harmony: our colours, range 15 → 120 m (transpiler), size grows with distance, lifetime stretched. Damage applied with `ModifyStats Health` makes no DamageResponse, so it is found by watching health and shown with `DamageText.Create` too. `DamageText` takes logical world positions (it subtracts `Origin.position`); for IMGUI drawing use `entity.transform.position` (scene space, floating origin).
- Perk scaling: one triggered/passive effect per perk level with `ProgressionLevel ... Equals N` (Ragdoll force/range cannot read `@cvar`; CVarCompare, ModifyStats, RandomRoll, AddBuff duration and passive values can).

## Build
- Uses the Windows .NET Framework compiler `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` → **C# 5 only** (no `$""`, `?.`, `=>` members).
- References the game's `7DaysToDie_Data/Managed` DLLs via a path relative to the repo, so the repo must live in `<game>/Mods/AposMod`.
- A running game locks `AposMod.dll`; close the game before building.
- Run scripts with `& script.ps1`; `-ExecutionPolicy Bypass` is blocked.
- Runtime reflection on Assembly-CSharp fails under .NET Framework. To read game code use **Mono.Cecil** from `Mods/0_TFP_Harmony/Mono.Cecil.dll` in PowerShell (`Add-Type`, `AssemblyDefinition.ReadAssembly`): fields, method signatures and IL. To confirm an API, test-compile a small probe `.cs` against the Managed DLLs.

## Gotchas found the hard way
- Never put a `ProgressionLevel` requirement in an effect group that grants `AttributeLevel`/`SkillLevel`/`PerkLevel` (e.g. `buffPerkCharismaticNature`): perk levels are calculated from those passives, so the check re-enters itself and the game hangs and crashes without a log. Use a cvar set by the perk (vanilla does; AposMod Leader uses `aposLeader`).
- `target="selfOtherPlayers"` skips the source entity: vanilla Charismatic Nature buffs only OTHER players, never the perk owner (MinEventActionTargetedBase.CanExecute).
- A zombie killed by `ModifyStats Health` has no killer: no XP, no quest/challenge credit (vanilla then shows a "1"). Area damage (splinters, Ricochet, reactions, Overkill, Shrapnel...) goes through `AposSplash.Deal` (AposCombat.cs) as a real hit in the player's name; XML effects set `aposSplashDmg` + the marker buff `buffAposSplash`, and `AposSplash.ProcessXml` deals it with the buff instigator as the attacker.
- In a `count="all"` lootgroup (e.g. the final chests `groupReinforcedChestT*`, `groupHardenedChestT*`, `groupBuriedTreasure`) an item's `prob` is **ignored** unless it has `force_prob="true"` (`LootContainer.SpawnAllItemsFromList`): without it the item always spawns.
- A lootgroup must be **defined before it is referenced**; otherwise loot.xml fails to load and world generation breaks (player falls through the ground).
- A mod with a DLL is skipped entirely (XML too) when the game runs with EasyAntiCheat. Launch `7DaysToDie.exe -noeac`. The log shows `Loaded Mod: AposMod` when it worked.
- Ammo item effect groups fire together with the weapon's events (ItemValue.FireEvent forwards to the loaded ammo) — that is how the slug-only knockback works.
- Harmony (HarmonyX) lives in `Mods/0_TFP_Harmony/0Harmony.dll` (restored by a full Steam "verify files"; it was missing before). Reference it from there when writing Harmony patches.
- An arrow / bolt hit (ProjectileMoveScript.checkCollision -> ItemActionAttack.Hit) gets the LAUNCHER as DamageSource.AttackingItem, not the ammo. Use `AposProjectiles.AmmoOf(source)` (the projectile being processed). `ItemActionCatapult.GetStrainPercent` is the last shot's draw and never resets; the live draw is `ItemActionDataCatapult.m_bActivated` + `m_ActivateTime / m_MaxStrainTime`.
- `player.motion` does not move the local player (vp_FPController); move it with `SetPosition` steps.
- Ranged AOE: `target="positionAOE"` hits around the impact/hit point (ammo `onProjectileImpact`, player `onSelfPrimaryActionRayHit`); arrows/bolts cannot pierce via XML (projectiles ignore EntityPenetrationCount).
- Custom UI sprites (buff icons etc.): `UIAtlases/UIAtlas/<name>.png` (white on transparent, tinted by `icon_color`), referenced by file name, e.g. `ui_apos_bloodsucker`. `Source/gen_buff_icons.ps1 -Out UIAtlases/UIAtlas -Preview <png>` draws the frenzy/adrenaline/evasion/haste/lungs icons.
- Pictograms drawn by C# (IMGUI): `Icons/*.png` loaded with `ImageConversion.LoadImage` from `AposSettings.ModPath` (elite modifier badges).
- Tab (backpack) and E (activate) open the same `XUiC_Radial` as the R ammo wheel: a short tap is the normal action, holding past `displayDelay` shows the wheel. Never shorten the delay in `XUiC_Radial.Open` (that broke Tab/E with a bow); the bow patch is on `ItemActionAttack.SetupRadial`.
- Game logs: `%APPDATA%/7DaysToDie/logs/output_log_client__*.txt`.
- A perk's `effect_description` lines often sit in the same `effect_group` as its effects (e.g. Gunslinger). Removing the whole group also removes the level descriptions, and the perk window then lists raw passives ("EntityDamage: 110%..."). Remove single `triggered_effect`/`passive_effect` nodes instead.
